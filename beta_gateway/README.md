# ChatSeek 内测网关

> 此目录保留可选的自托管补贴额度实验。公开版 ChatSeek 默认使用个人 API 配置，不提供邀请码界面；普通使用者无需部署本目录。若自行启用网关，需要额外集成激活入口和凭证配置。

客户端只持有个人内测 token；共享 DeepSeek Key 只放在服务器。当前网关按模型请求计数，查询规划、回答、每批总结、媒体识别分别计次。普通问题通常至少 2 次；200 次请求不承诺恰好 100 次问答。

默认 20 个累计激活名额，每码一份安装凭证，首次激活后 **3 × 24 小时**到期；每码 200 次模型请求，每个北京时间自然日 100 次，token 预算 500 万。全体 token 预算默认 1 亿。可先发 3 个码，实测通过后再增加。只生成/分发少量邀请码也能进一步限制招募人数。

## 部署

腾讯云中国大陆从购买、备案到 HTTPS、限流与备份的步骤见 [部署操作说明](DEPLOY.md)。可用 `.venv/bin/python scripts/build_beta_gateway.py` 从项目根目录生成独立部署包；无需构建 Mac 应用。

服务器仅需 Python 3 标准库，无需上传微信、向量库或客户端依赖。复制 `server.py` 到服务器目录；设定 `DEEPSEEK_API_KEY` 后运行：

```sh
python3 server.py --db /srv/chatseek-private/usage.sqlite3 serve --port 8787
```

Key 通过服务器的环境配置或权限为 `0600` 的服务环境文件提供；不要写入客户端、Git、启动参数或发给测试者。进程由 systemd 等服务管理器守护。参考同目录的 `chatseek-gateway.service`。网关只监听 `127.0.0.1`，必须由 HTTPS 反向代理提供公网入口，例如 Caddy：

```caddyfile
api.your-domain.com {
    request_body {
        max_size 8MB
    }
    reverse_proxy 127.0.0.1:8787
}
```

用实际域名替换示例，再让客户端填写 `https://api.your-domain.com`。打包客户端时可加 `--gateway-url https://api.your-domain.com` 预填网关地址，用户只需输入自己的邀请码。

服务器证书、DNS、防火墙、进程托管和备份需在你的服务器完成。不要直接开放 8787，不要在代理/APM 中记录请求体或 Authorization 头；为激活入口添加每 IP 速率限制及连接数限制。当前按单实例 + 本机 SQLite 设计，不应启动多套独立账本。

## 管理名额与额度

所有管理命令只在服务器终端执行，无公网管理接口。以下均在 `server.py` 所在目录运行，对同一 `--db` 操作：

```sh
# 发一个码；默认 3 天，也可以逐个指定额度
python3 server.py --db /srv/chatseek-private/usage.sqlite3 issue --label tester-01 --days 3 --calls 200 --daily 100 --tokens 5000000

# 查看激活时间、到期时间、请求次数、预扣与模型报告用量（不显示密钥）
python3 server.py --db /srv/chatseek-private/usage.sqlite3 list

# 立即停用列表中的某个 ID
python3 server.py --db /srv/chatseek-private/usage.sqlite3 revoke 1

# 调整全体累计激活名额及 token 总预算
python3 server.py --db /srv/chatseek-private/usage.sqlite3 limits --seats 20 --tokens 100000000
```

邀请码为不可预测的随机值，数据库只存码和 token 的 SHA-256 摘要。发行时只显示一次邀请码，请自行妥善保存及单独发给对应测试者。撤销/到期不会腾出累计名额；确需扩大招募时提高 seats。同一安装重试激活不新增名额、不延期，会轮换 token；旧 token 立即失效。丢失安装凭证后不能直接在另一台电脑用同码重新激活，需要管理员处理或另发邀请码。

## 计量与隐私边界

- 每次向模型发起请求前，SQLite `BEGIN IMMEDIATE` 原子检查并预扣。并发请求不能穿透次数/名额上限；同邀请码最多一个处理中请求，全体最多四个。
- 文本请求预扣 UTF-8 字节数、协议余量及输出上限；含画面请求按完整百万 token 上下文保守预扣。成功得到有效 `usage.total_tokens` 后按实际报告结算。预扣大于剩余预算时会提前拒绝，即使最终实际消耗可能更低。
- 上游失败或超时仍计一次请求；没有可靠 usage 时保留预扣，避免通过断线绕过额度。服务崩溃时未完成预扣也保留；360 秒后释放并发占位。
- 单次文字材料最多 192000 UTF-8 字节、4 张画面、8192 输出 token。超出时要求缩小日期范围；不会偷偷截断原文。模型固定在 Flash 系列、关闭 thinking，忽略客户端 tools/n 等额外参数。
- token 预算与实际人民币账单并非同一单位，输入/输出/缓存单价不同。图片预扣依赖模型容量，异常 usage 可能超过预估；**服务商账户预算或余额限制仍是最终费用保护**。服务端记录报告 token，但未实现按价格版本计算人民币账单。
- 为先核对用量，内测网关先等模型完整返回，再发送兼容现有客户端的 SSE；补贴模式当前不逐 token 显示，界面会等待完整回答。自带 Key 的直连模式保留原生流式输出。
- 网关会在内存中接收并转发聊天材料及媒体，不写入账本或 HTTP 日志；账本只有邀请码标识、安装摘要、激活时间、到期、次数与用量。反向代理和部署平台须另行配置日志策略。不能宣传聊天“从不经过产品方服务器”。
- 绑定的是本机随机安装凭证，不是硬件鉴权。复制激活文件可共享同一额度，服务端的并发、到期和用量限制仍有效。本方案控制你补贴的 AI 服务；不能禁止安装包转发或用户用自己的 Key 使用本地功能。

本地自动测试覆盖激活重试、设备绑定、并发名额、并发预扣、到期、撤销、全局预算、失败预扣及 HTTP/SSE 转发；没有使用真实模型或发送私人聊天。公网部署、真实费用和其他 Mac 的首次初始化需要另行实测。
